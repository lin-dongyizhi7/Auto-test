# 多机器多应用连接重构说明

## 概述

本次重构将原有的单机器单应用连接架构升级为多机器多应用连接架构，支持同时连接多台被测试机器，并在每台机器上管理多个应用程序的自动化测试。

## 架构变化

### 原有架构
```
前端 → 后端 → 单台被测试机器
```

### 新架构
```
前端 → 后端 → 测试服务器 → 多台被测试机器 → 多个应用程序
```

## 核心组件

### 1. 后端重构 (backend/main.py)

#### 新增API端点
- `GET /machines` - 获取可用机器列表
- `GET /apps` - 获取可用应用列表
- `POST /set-target` - 设置当前操作目标机器和应用
- `GET /current-target` - 获取当前操作目标
- `POST /screenshot` - 获取当前目标应用的截图

#### 数据模型更新
- `MachineInfo` - 机器信息
- `AppInfo` - 应用信息
- `MachineAppTarget` - 机器应用目标
- `CurrentTarget` - 当前目标

#### 连接管理
- 连接到测试服务器（而非直接连接被测试机器）
- 支持多机器多应用的目标设置
- 操作前必须设置目标机器和应用

### 2. 前端重构

#### 类型定义 (frontend/src/api/types.ts)
- 新增多机器多应用相关的TypeScript类型定义
- 更新操作请求和响应的数据结构

#### API操作 (frontend/src/api/operation.ts)
- 重构API调用方法，支持多机器多应用
- 新增机器和应用管理相关的API调用

#### 状态管理 (frontend/src/stores/operation.ts)
- 重构Pinia store，支持多机器多应用状态管理
- 新增机器列表、应用列表、当前目标等状态
- 重构操作逻辑，确保操作前已设置目标

#### 用户界面 (frontend/src/views/Operation.vue)
- 新增测试服务器连接面板
- 新增目标机器和应用选择面板
- 重构操作面板，只有在设置目标后才显示
- 新增截图功能面板
- 重构操作日志显示

## 使用流程

### 1. 连接测试服务器
1. 在"测试服务器连接"面板中输入测试服务器地址和端口
2. 点击"连接"按钮建立连接

### 2. 选择目标机器和应用
1. 连接成功后，在"目标机器和应用"面板中选择目标机器
2. 选择目标应用
3. 点击"设置目标"按钮确认

### 3. 执行自动化操作
1. 设置目标后，各种操作面板才会显示
2. 在相应面板中配置操作参数
3. 点击执行按钮执行操作

## 技术特点

### 1. 分层架构
- **通信层**: 测试服务器与被测试机器之间的通信
- **业务层**: 多机器多应用的管理和操作
- **展示层**: 用户界面的交互和状态管理

### 2. 状态管理
- 使用Pinia进行集中状态管理
- 支持异步操作和错误处理
- 实时更新连接状态和操作日志

### 3. 类型安全
- 完整的TypeScript类型定义
- 编译时类型检查
- 运行时数据验证

### 4. 用户体验
- 响应式设计，支持不同屏幕尺寸
- 实时状态反馈和操作日志
- 直观的机器和应用选择界面

## 部署说明

### 1. 测试服务器
- 运行 `test_communicator.py` 作为测试服务器
- 监听8889端口，等待被测试机器连接

### 2. 被测试机器
- 运行 `tested_communicator.py` 作为客户端
- 连接到测试服务器，注册机器和应用信息

### 3. 后端服务
- 运行 `backend/main.py` 提供API服务
- 连接到测试服务器，管理多机器多应用

### 4. 前端应用
- 运行 `frontend/` 目录下的Vue应用
- 通过API与后端通信，执行自动化操作

## 配置说明

### 1. 端口配置
- 测试服务器: 8889
- 被测试机器: 8888
- 后端API: 8080
- 前端开发服务器: 3000

### 2. 网络配置
- 确保测试服务器可以被所有被测试机器访问
- 确保前端可以访问后端API
- 配置防火墙规则允许相应端口通信

## 注意事项

### 1. 操作前必须设置目标
- 所有自动化操作都需要先设置目标机器和应用
- 未设置目标时，操作面板不会显示

### 2. 连接状态管理
- 断开连接后，所有状态会被清空
- 重新连接后需要重新设置目标

### 3. 错误处理
- 网络异常、操作失败等错误会在日志中显示
- 操作失败时会有相应的错误提示

### 4. 性能考虑
- 大量机器和应用时，列表加载可能需要时间
- 截图功能会传输图片数据，注意网络带宽

## 扩展功能

### 1. 批量操作
- 支持同时对多台机器执行相同操作
- 支持操作序列的批量执行

### 2. 监控功能
- 实时监控机器和应用状态
- 操作执行结果的统计分析

### 3. 脚本管理
- 支持保存和加载操作序列
- 支持定时执行自动化脚本

## 故障排除

### 1. 连接失败
- 检查网络连接和防火墙设置
- 确认测试服务器正在运行
- 检查端口配置是否正确

### 2. 操作失败
- 确认已设置正确的目标机器和应用
- 检查被测试机器上的应用程序状态
- 查看操作日志中的错误信息

### 3. 界面问题
- 检查浏览器控制台是否有JavaScript错误
- 确认前端依赖包已正确安装
- 检查API响应格式是否正确

## 总结

本次重构成功将单机器单应用架构升级为多机器多应用架构，提供了更强大的自动化测试能力。新的架构支持：

1. **多机器管理**: 同时连接和管理多台被测试机器
2. **多应用支持**: 在每台机器上管理多个应用程序
3. **灵活目标设置**: 动态选择操作目标
4. **增强的用户体验**: 更直观的界面和更好的状态反馈
5. **可扩展性**: 为未来的功能扩展提供了良好的基础

重构后的系统更适合企业级自动化测试需求，支持复杂的多环境测试场景。
